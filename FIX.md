# Инструкция по обновлению и выпуску релиза

Этот файл описывает процесс поддержки актуального форка (с вашими патчами) относительно главного репозитория `grok-build`, а также процесс автоматической сборки новых релизов через GitHub Actions.

## 1. Обновление из апстрима (upstream)

Чтобы подтянуть последние изменения от разработчиков xAI и наложить ваши патчи (например, исправление ломания кавычек) поверх них, выполните следующие шаги:

```bash
# Добавьте оригинальный репозиторий как upstream, если еще не сделали этого
git remote add upstream https://github.com/xai-org/grok-build.git

# Получите последние изменения
git fetch upstream

# Перебазируйте вашу ветку поверх актуальной ветки main из апстрима
# Важно: убедитесь, что вы находитесь в ветке с вашими патчами (например, fix-bash-quotes-escaping)
git rebase upstream/main
```

## 2. Разрешение конфликтов (если возникнут)

В процессе `rebase` могут возникнуть конфликты (если разработчики апстрима изменили те же строки, что и вы).
Если это произошло, git остановит процесс перебазирования и выведет список файлов с конфликтами.

1. Откройте конфликтующие файлы в вашем редакторе и найдите маркеры конфликтов (`<<<<<<<`, `=======`, `>>>>>>>`).
2. Отредактируйте код так, чтобы сохранить логику апстрима и ваши исправления. Уберите маркеры конфликтов.
3. Добавьте разрешенные файлы в индекс:
   ```bash
   git add <имя_файла>
   ```
4. Продолжите процесс перебазирования:
   ```bash
   git rebase --continue
   ```
*(Повторяйте эти шаги, пока `rebase` не завершится успешно).*

## 3. Выпуск релиза

Когда код обновлен и все работает корректно, можно выпустить новую версию. Мы используем схему версионирования "Версия апстрима + буква (например, a)". 
Например, если версия `0.2.998`, ваш тег будет `v0.2.998a`.

1. Запушьте ваши обновления в ваш форк. Так как вы сделали rebase (переписали историю), вам понадобится флаг `--force` (или `--force-with-lease`):
   ```bash
   git push origin HEAD --force-with-lease
   ```

2. Создайте тег для релиза:
   ```bash
   git tag v0.2.998a
   ```

3. Запушьте тег на GitHub:
   ```bash
   git push origin v0.2.998a
   ```

### Что произойдет дальше?
Как только вы запушите тег (`v*`), автоматически запустится рабочий процесс GitHub Actions (`release.yml`), который:
- Скачает нужную версию Rust и зависимости.
- Передаст имя тега (без `v`) внутрь бинарника, чтобы `grok --version` отображал, например, `0.2.998a`.
- Соберет бинарники `grok` для macOS и Linux.
- Создаст релиз на странице проекта в GitHub и прикрепит к нему готовые исполнимые файлы.
